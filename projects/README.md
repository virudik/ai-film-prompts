# Несколько проектов в одном репозитории (решение владельца 20.10.2026)

Статус: действует после слияния PR «Переключатель проектов». Проверено: 20.10.2026.

Владелец ведёт несколько проектов: **Серёгиус** (основной фильм), **Котмонавты** (спин-офф про котов), **Кот детектив**, **Разное** (независимые ролики). У каждого проекта свои сцены, промты, референсы, инструкция, хендоф и очередь запуска. Работают они независимо, а инструменты общие: один сайт, одни роботы, одни правила записи.

## Где что лежит

| | Серёгиус | Любой другой проект `<id>` |
|---|---|---|
| Папка | корень репозитория (как раньше, ничего не переезжало) | `projects/<id>/` |
| Мастер промтов | `video-prompts.md` | `projects/<id>/video-prompts.md` |
| Статус мастера | `project-status.json` | `projects/<id>/project-status.json` |
| Инструкция проекта | 7 инструкций в корне | `projects/<id>/INSTRUCTIONS.md` (только своё; общее — 7 инструкций) |
| Хендоф | `NEW-CHAT-HANDOFF.md` | `projects/<id>/HANDOFF.md` |
| Референсы | `character-references.json`, `references/` | `projects/<id>/character-references.json`, `projects/<id>/references/` |
| Очередь запуска | `ops/topview-launch-queue.json` | `projects/<id>/ops/topview-launch-queue.json` |
| Замок канона | `ops/canon-lock.json` | `projects/<id>/canon-lock.json` |
| Решения по сценам | `review-ledger.json` | `projects/<id>/review-ledger.json` |
| Порядок сцен | `film-order.json` | `projects/<id>/film-order.json` |
| Телеметрия Topview | `topview-status.json` | общий файл `projects/topview-projects.json` (поле `project`) |

Реестр — `projects/projects.json` (id, название, алиасы для распознавания, пути). Проверка — `python3 scripts/projects.py . validate`.

**Номера сцен у каждого проекта свои**, с 1. «Сцена 3» без названия проекта — это Серёгиус. Пути к картинкам в любом мастере пишутся от корня репозитория (`projects/kotmonavty/references/luchik.jpg`), тогда они одинаково открываются на сайте и в Topview.

## Как понять, к какому проекту сообщение владельца

1. Владелец называет проект: «в проекте Котмонавты…», «в Коте детективе…», «в Разном…». Проект — тот, что назван.
2. Проект не назван — это **Серёгиус** (так было всегда). «Коты», «Лучик», «РосКОТмос» сами по себе проект не меняют: они есть и в Серёгиусе.
3. В одном сообщении несколько проектов — разделить на части и сделать каждую в своём проекте. Если часть не относится явно ни к одному — спросить владельца одним вопросом.
4. Если сомнение (например, «сделай сцену с котами в космосе» без проекта) — по умолчанию Серёгиус, и в ответе сказать, что сделано в Серёгиусе и можно перенести.
5. Проверка: `python3 scripts/projects.py . detect "<текст владельца>"` — выдаёт проект, или `null` и список названных проектов.

В ответе владельцу агент всегда называет проект: «Котмонавты, сцена 2 — готово».

## Правила, которые у всех проектов одинаковые

Всё из 7 инструкций в корне действует для каждого проекта: шаблон промта (`PROMPT-STYLE-GUIDE.md` §5А), две версии промта (§7А), reference-first, «технический success ≠ одобрение», запуски только безлимит через сайт Topview под входом владельца (0 кредитов), платные запуски только сам владелец, ничего не одобрять, не удалять и не перезапускать автоматически, творческое — владельцу. Своё у проекта (сюжет, персонажи, стиль) — в его `INSTRUCTIONS.md`; если там что-то противоречит 7 инструкциям, побеждают 7 инструкций, а владельцу говорится о противоречии.

## Параллельная работа: замки

- **Замок проекта** `projects/<id>/canon-lock.json` — для правок только внутри `projects/<id>/` (мастер, референсы, очередь, хендоф и инструкция проекта). Пока Claude держит замок Котмонавтов, ChatGPT может держать общий замок и работать с Серёгиусом: файлы не пересекаются.
- **Общий замок** `ops/canon-lock.json` — для всего остального: Серёгиус (корень), 7 инструкций, сайт, скрипты, workflow, этот файл и реестр.
- Работа, которая задевает и проект, и общее (например, новый общий скрипт) — оба замка или по очереди.
- Порядок взятия и освобождения — тот же, что в `ops/CANON-LOCK.md` (до 45 минут, последним коммитом освободить; просроченный замок свободен). Скрипт: `python3 scripts/canon_lock.py . acquire --project <id> --holder claude:<тред> --task "…" --push`.
- Git всё равно отклоняет устаревший push: отклонён — перечитать `main` и повторить с нуля.

## Правка мастера проекта

`git pull` → замок проекта → минимальная правка `projects/<id>/video-prompts.md` → `python3 scripts/projects.py . status --project <id> --write` (health=ok) → коммит мастера вместе со статусом → освободить замок → проверить сайт (`index.html?p=<id>`). Робот `projects-sync.yml` при каждом пуше в `projects/**` сам пересобирает и проверяет статусы, если агент забыл.

## Сайт

Слева сверху переключатель проектов. Адрес проекта — `index.html?p=<id>` (для Серёгиуса — просто `index.html`); так же `references.html?p=<id>` и `film.html?p=<id>`. Страница та же, данные берутся из папки проекта (`projects.js` подменяет пути). Блоки, которые есть только у Серёгиуса (монтажный разбор, архив MP4 в Drive), в других проектах скрыты. Слоты Topview показываются общими: «занято N из 6 на всех проектах».

## Кнопки владельца на сайте

- Кнопки сцен другого проекта записывают в Supabase ту же строку, что и у Серёгиуса, плюс `value = "project:<id>"`; текстовая задача — с началом `[проект: <id>]`; кнопка у картинки — по пути картинки; кнопки задачи Topview («Брак», «Не ждать») — по задаче из `projects/topview-projects.json`.
- Роботы Серёгиуса (фазы 1–3 `sync-from-drive.yml`) такие строки **не трогают**. Их применяет фаза 4 (`scripts/robot_project_actions.py`): очередь проекта (▲ ▼ ✕ «в очередь», только при свободном замке проекта), решения по сценам и задачам — в `projects/<id>/review-ledger.json`, «В фильме» / «Не нужна» — сцена убирается из мастера проекта, номер резервируется. Задачи владельца попадают во входящие `ops/owner-tasks.json` с полем `project`.

## Topview

- Аккаунт один, **слоты общие: 6 на все проекты**. Свободно = 6 − `topview-status.json.occupied_slots` − число `active` в `projects/topview-projects.json`.
- Робот телеметрии узнаёт задачу другого проекта по точному (или нормализованному) совпадению промта ровно с одной активной сценой ровно одного мастера проекта и пишет её в `projects/topview-projects.json` (сцену и мастер Серёгиуса не трогает). Неизвестная задача — как раньше: робот ждёт (`hold`) и пишет в issue `topview-events`.
- Очередь: ChatGPT смотрит готовые элементы во всех очередях; один свободный слот, а готовы несколько проектов — сначала проект выше в `launch_order` реестра, внутри проекта — наименьший `priority`. Владелец меняет порядок фразой «в проекте X запускать первым» (агент правит `launch_order`). Квитанции — в `projects/<id>/reports/`.
