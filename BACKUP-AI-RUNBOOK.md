## 1. Нельзя начинать с редактирования

Новый агент сначала читает **все семь** документов из `main` (`git pull`) в порядке: `NEW-CHAT-HANDOFF.md`, `SYNC-RUNBOOK.md`, `AI-PROJECT-GUIDE.md`, `PROMPT-STYLE-GUIDE.md`, `USER-GUIDE.md`, `README-AI-SYNC.md`, `BACKUP-AI-RUNBOOK.md`. Затем: свежий `video-prompts.md`; живые `project-status.json`, `topview-status.json`, `instruction-sync-status.json`, `monitor-role.json`; открытые задачи владельца в Supabase `owner_decisions`; при сюжетной работе — `film-analysis.md`, `film-backlog.md`, затем релевантный Notion `Кино`. Только после этого takeover считается завершённым. Формат takeover — полное чтение (решение D7 о сокращённом чтении — `AI-PROJECT-GUIDE.md`).

## 2. Capability preflight

Перед записью агент должен доказать, что конкретное окружение умеет: читать и писать репозиторий `virudik/ai-film-prompts` (`git pull`, `git push`); обновлять `SYNC-TRIGGER.txt`; запускать проверки (`scripts/validate_site.py`, тесты, `scripts/cert_github.py`); проверять Actions / статус / Pages. Если записи в репозиторий нет — агент **review-only**: он не создаёт новый master и не изображает, что запись выполнена.

## 3. Источники истины

- GitHub `main` — канон: master, 7 инструкций, Control Center, машинные статусы, Pages.
- Резервные копии (только чтение): Drive, Notion-указатель, Claude Project, ChatGPT Project, Library.
- Notion `Кино` — сюжет, идеи, история. Topview — телеметрия. Supabase — backend комментариев и решений владельца.

Ни одно из хранилищ, кроме `main`, не становится prompt master.

## 4. Правила master

Scene ID стабильны, закрытые никогда не переиспользуются; без `v2` / `final` / `copy`; перед записью `git pull`; минимальная правка; оглавление / счётчики / meta согласованы; slow-сцены автоматически не перезапускаются; Topview success ≠ approval; `NEEDS_FIX` ≠ разрешение переписывать всё. Если следующий Scene ID однозначно следует из свежего master, агент сам берёт следующий неиспользованный ID и не задаёт лишнего вопроса (новую сцену из Topview-задачи заводят только с согласия владельца).

## 5. Правила prompt-writing

Перед новым или существенным промтом: прочитать `PROMPT-STYLE-GUIDE.md`, свежий master, 1–2 близкие актуальные сцены. Промт соответствует master-level сложности, а не короткому описанию. Обязательные типовые элементы: точные refs и приоритет identity; story flow / timeline; camera / continuity; performance; dialogue / vocal / lip sync; свет, материалы, окружение; native audio; scene-specific negative prompt; `FRAME FILL / NO BARS`. Утверждённый model sheet сильнее случайного сходства кадра. Каждый автономный production-промт содержит собственный короткий `CHARACTER APPEARANCE / IDENTITY LOCK`; зависимость от внешнего «shared block above» — отклонение от стандарта, исправляется в master, а не просьбой к владельцу вручную доклеить описание. Качество оценивать по смыслу: самостоятельный блок для копирования, реальная защита внешности, владение референсами и приоритет, выполнимый тайминг, связная камера и continuity, негативы по рискам, без лишних повторов. Старые полнотекстовые примеры каноном не считаются. Правила слотов Topview — `SYNC-RUNBOOK.md`, не prompt guide.

## 8. Material Change Duty

Если агент внедрил постоянное нововведение (функцию сайта, backend, prompt rule, sync / recovery behavior, правило источника истины, новый статус), он обязан **в том же сеансе**: обновить релевантные инструкции; тот же handoff; prompt guide, если применимо; выполнить `cert_github.py` и push; проверить сайт и статус; обновить Notion-указатель; резервные копии (Library и др.) — best-effort, без интерактивных подтверждений владельца и без блокировки основного цикла. Изменение кода без документации не считается законченным.

## 9. Control Center — текущий baseline

Сайт умеет: активные сцены и полные промты; объединённую таблицу slow / Topview; индикатор синхронизации; референсы; светлую / тёмную тему; «Контрольный отпечаток»; отдельную сворачиваемую секцию «💬 Комментарии, идеи и предложения» сразу ниже; комментарии и ответы Supabase без входа в GitHub; панель «🔑 Владелец» с кнопками решений. Кнопки «Архив GitHub» нет. Комментарии: Supabase `ai-film-comments` (ref `vzohfatqzyioydtgjiyd`), Edge Function `submit-comment`; RLS + honeypot + 5 сообщений / 10 мин / IP; admin / service-секретов в публичном HTML нет; прав на изменение master нет.

Owner-facing контракт, который нельзя откатывать: крупно `M из 6` занятых слотов Topview (ниже `Свободно Y · N сцен`), подробный заголовок `занято M из 6 · свободно Y · timestamp`; сводка работ без сырых `W5…W15`; компактное левое меню (Service Files и Filters свёрнуты, активный фильтр виден); плавающая «↑ Наверх». Не возвращать старый вариант, где свободные слоты скрыты или карточка считает только unique slow-сцены.

## 10. Site-only edit procedure

Править `index.html` в `main`; затем `scripts/validate_site.py`, дубли id, проверка секретов, Pages. Данные сцен и промтов в HTML не зашивать. Постоянное изменение — Material Change Duty.

## 11. Topview safety

Canonical slow = `project-status.json.slow_scenes`. Привязка задачи: точная задача; смысл всей текущей сцены; совпадение модели и референсов; `verified=true` только при доказательстве. Пассивная телеметрия никогда не одобряет, не снимает slow, не правит master и не перезапускает автоматически. Узкое write-исключение монитора: добавить **существующий Scene ID** в canonical slow при доказанной новой задаче существующей сцены (точное совпадение промта или явное происхождение); новый Scene ID из Topview — только с согласия владельца. Это не разрешение approve / delete / slow-clear / rerun.

Привязка существующей сцены считается доказанной только при совпадении промта точно или с точностью до нормализации (допустимы лишь несемантические различия `@image` ↔ `<<<Image>>>`, пробелы и переводы строк, формат токенов) либо при явном происхождении, плюс совместимые модель, длительность и референсы. Общее смысловое сходство не даёт права ни привязать, ни тихо отбросить задачу. Известный task ID — не новый intake; одна задача не импортируется дважды; повторный запуск существующей сцены не отбрасывается как «семантически похожий» без обновления привязки и slow.

## 12. Известные проблемы восстановления

Одновременные писатели → перечитать `origin/main` и повторить с нуля. BOM / CRLF → master — UTF-8 без BOM и LF; инструкции хранят собственную конвенцию файла. Устаревший сертификат → обновить `cert_github.py`. Исторические checkpoint-и не считать живыми. Устаревшая привязка Topview → сравнивать со свежим телом сцены. Старое письмо об ошибке GitHub → сравнить время с новым успешным запуском и живым статусом.

## 13. Notion и резервные копии

Notion: сюжет, идеи, история; операционная страница `AI Film — Актуальная инструкция / Handoff`; `Важные промты` — архивный банк. Library: резервный кэш — хранить актуальные копии семи документов и recovery summary / status; **никогда не предпочитать Library канону в `main`**. Устаревшая или ожидающая Library не блокирует работу и не требует запросов разрешений у владельца.

## 14. Правило поведения сменщика

Если ответ есть в каноне или статусе: не спрашивать владельца повторно; не импровизировать другую архитектуру; не перекладывать ручную работу на владельца, если есть инструменты; продолжать с текущего состояния; при ограничении инструмента честно назвать конкретный недоступный шаг. Цель takeover: владелец говорит только новую творческую или рабочую задачу, а сменщик уже знает инфраструктуру и процесс.

## 15. Character registry и монтажный контекст до takeover

До вступления в роль резервный агент открывает `references.html`, читает `character-references.json` и сопоставляет имена, алиасы и model sheets с текущим master; владелец вправе называть персонажей коротко — агент сам восстанавливает внешность, костюм и маппинг референсов. Также открывает `Seregius_montazhny_razbor.html` (и `-2`), сверяет с `film-analysis.md` и `film-backlog.md`, строит компактную рабочую карту фильма и текущих сюжетно-монтажных проблем. Утверждённый индивидуальный model sheet сильнее группового сходства; текущий master сильнее устаревших метаданных сцен. Только при реально неоднозначном имени — вопрос владельцу.

## 16. Readiness gate резервного редактора

Перед «готов продолжать»: сквозной аудит `main` (7 инструкций, master, статусы, сайт) → референсы → монтажные источники → Notion-указатель. Library проверять как recovery-only кэш. Безопасный дрейф документации исправить по правилам authority; сюжет, master и approval без решения владельца не менять.

Если Topview — единственный оставшийся источник, точные входные изображения задачи восстанавливаются через мост ниже, а не повторной загрузкой владельцем.

**Topview exact-input binary recovery bridge.** Когда метаданные задачи Topview дают только S3 / source-пути, а `download_topview_canvas_nodes` возвращает короткоживущие авторизованные URL, точные байты источника можно сохранить без повторной загрузки владельцем:
1. создать / использовать авторизованный Topview Canvas и добавить точные S3-источники входов задачи как media nodes;
2. вызвать действие загрузки Canvas небольшими пачками, чтобы получить свежие авторизованные URL;
3. создать временную Google Slides-колоду по одному пустому слайду на изображение и вставить каждый URL через `createImage`;
4. экспортировать колоду в PPTX и извлечь точные байты из `ppt/media/`;
5. сохранить байты в `references/scenes/scene-N/` (если ими пользуется сцена), в рабочий пакет на Drive и в Library; записать в manifest сцены исходный task ID, роль в Topview (`Image1`, `Image2`…), sha256, ID файлов;
6. подписанный временный URL Topview никогда не публиковать (он истекает); временную колоду удалить.
