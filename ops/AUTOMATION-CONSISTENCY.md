# Сверка инструкций и автоматизаций

Статус: действует. Проверено: 26.10.2026.

Сверку делает ChatGPT в существующем недельном цикле (воскресенье 08:55 МСК), после изменения общих правил и при обнаруженном противоречии. Новых расписаний нет. Порядок чистки — NEW-CHAT-HANDOFF.md. Данные и творческие решения не меняются ради прохождения проверки.

1. Прочитать свежие main: семь инструкций, CLAUDE.md, ops/OWNER-TASKS.md, ops/CANON-LOCK.md, ops/TOPVIEW-EVENT-WAKE.md, очередь/manifest, ops/relay-wake.json, ops/claude-wake.json и automation-monitor-status.json. Правило живёт в профильном документе; остальные тексты ссылаются на него. Сверить полномочия, исключения замка, трёхчасовой порог, ответ в тот же тред и сроки архивирования. Не переносить исторические зависимости сцен в действующий prompt.
2. Прочитать через Automations peek оба существующих задания: 6acae6ab433481919e88665c520b8ef2 (часовое HH:55 Europe/Moscow) и 6adc585e7ac08191bb93825117dc7213 (Relay, без расписания). Проверить полный prompt, enabled, расписание и фактическую подписку Relay: одна relay.message, прежние фильтры. Недоступный источник = not_checked с причиной, а не подтверждение. Не изменять расписания/подписку при обычной правке prompt; при webhook-update передать полный существующий набор triggers. После изменения снова прочитать и сравнить точный текст.
3. Выполнить `python3 scripts/check_instruction_consistency.py .`. Для проверки живых заданий передать `--automations` с путём локального временного JSON: checked_at (UTC), automations (только id, prompt, schedule, default_timezone, is_enabled, updated_at), relay_subscriptions (только id, event, arguments, active). Снимок свежий, не старше часа. Не сохранять полные prompts, результаты запусков, подписанные URL или секреты в репозиторий. `--write` сохраняет компактный reports/instruction-consistency.json с хешами и результатами. Без снимка скрипт честно пишет live_automations=not_checked.
4. Скрипт покрывает выбранные инварианты, не всё значение текста. Агент отдельно сопоставляет текущие зависимости/приоритеты очереди, границы полномочий и противоречащие формулировки; фиксирует результат и непроверенное в checkpoint. Сертификат 7/7 подтверждает байты, enabled/подписка — настройку; успех выполнения подтверждают собственные run/task receipts.
5. Проверить архив закрытых входящих по ops/OWNER-TASKS.md: полный перенос до удаления, сохранность ID/результатов, отсутствие активных задач в удаляемой части. Проверить иные журналы по штатной недельной процедуре. Не создавать пустой архив для видимости выполненной чистки.
6. Исправления — в разрешённом объёме, под соответствующим замком/CAS; после инструкций cert_github.py, нужные тесты, validate_site.py, canon_health.py, D7 и readback. Снимок до миграции сертификата — archive/ops/instruction-certificate-legacy-2026-10-26.json, история, не authority.

Шаблоны Project Instructions — USER-GUIDE.md. Их обновление в GitHub не доказывает замену текста в настройках ChatGPT/Claude Project: проверять этот слой отдельно при доступном интерфейсе, иначе явно отмечать непроверенным. Обычное отсутствие доступа к настройкам не блокирует работу по свежему main.

## Продолжение после смены чата (27.10.2026)

В недельной сверке выполнить `python3 scripts/continue_preflight.py . --require-short`: проверить фокус, связанный раздел и доказательства; не менять фокус из-за времени фоновой проверки. При изменении результатов сначала сверить канон, затем обновить recovery и пакет по `ops/CONTINUE-PROTOCOL.md`. Недельная чистка сохраняет связанные разделы незавершённых задач. Настройка Project и факт исполнения нового чата проверяются раздельно.
