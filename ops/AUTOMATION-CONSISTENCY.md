# Сверка инструкций и автоматизаций

Статус: действует. Проверено: 31.10.2026.

Сверку делает ChatGPT в существующем недельном цикле (воскресенье 08:55 МСК), после изменения общих правил и при обнаруженном противоречии. Новых расписаний нет. Порядок чистки — NEW-CHAT-HANDOFF.md. Данные и творческие решения не меняются ради прохождения проверки.

1. Прочитать свежие main: семь инструкций, CLAUDE.md, ops/OWNER-TASKS.md, ops/CANON-LOCK.md, ops/TOPVIEW-EVENT-WAKE.md, ops/LAUNCHER-COORDINATION.md, ops/slot-backup.json, очередь/manifest, ops/relay-wake.json, ops/claude-wake.json и automation-monitor-status.json. Правило живёт в профильном документе; остальные тексты ссылаются на него. Сверить полномочия, исключения замка, трёхчасовой порог, ответ в тот же тред и сроки архивирования. Не переносить исторические зависимости сцен в действующий prompt.
2. Прочитать через Automations peek три существующих задания: 6ae5e9d563f88191aa6da7c9ba1e05a0 (обычный ChatGPT, каждые два часа), 6acae6ab433481919e88665c520b8ef2 (Work-путь HH:55 Europe/Moscow) и 6adc585e7ac08191bb93825117dc7213 (Work Relay, без расписания). Проверить полный prompt, enabled, расписание и фактическую подписку основного Relay: одна relay.message, прежние фильтры. Отсутствующая подписка отдельного обычного адреса не блокирует его scheduled polling. Для scheduled исполнителя проверяется его peers.<surface>.automation_ids; active_automation_id — указатель обычного задания, не требование совпадения Work ID с ним. Недоступный источник = not_checked с причиной, а не подтверждение. Не изменять расписания/подписку при обычной правке prompt; при webhook-update передать полный существующий набор triggers. После изменения снова прочитать и сравнить точный текст.
3. Выполнить `python3 scripts/check_instruction_consistency.py .`. Для проверки живых заданий передать `--automations` с путём локального временного JSON: checked_at (UTC), automations (только id, prompt, schedule, default_timezone, is_enabled, updated_at), relay_subscriptions (только id, event, arguments, active). Снимок свежий, не старше часа. Не сохранять полные prompts, результаты запусков, подписанные URL или секреты в репозиторий. `--write` сохраняет компактный reports/instruction-consistency.json с хешами и результатами. Без снимка скрипт честно пишет live_automations=not_checked. Если версия скрипта покрывает лишь прежние два задания, это явно ограниченный результат: обычный исполнитель, peer allowlists, route_generation и foreground epoch дополнительно сверяются по профильному документу и `tests/test_launcher_coordination.py`.
4. Скрипт покрывает выбранные инварианты, не всё значение текста. Агент отдельно сопоставляет текущие зависимости/приоритеты очереди, границы полномочий и противоречащие формулировки; фиксирует результат и непроверенное в checkpoint. Сертификат 7/7 подтверждает байты, enabled/подписка — настройку; успех выполнения подтверждают собственные run/task receipts. Сверять независимый подхват обоих исполнителей, точный уникальный holder/lease, одноразовый submitting intent, запрет повторного unknown Create и передачу foreground ответственности по «Продолжай». Сообщённое исчерпание Work не равно измеренной квоте; возврат предпочтения требует свежего доказательства восстановления. GET-скан и запуск задания не доказывают GUI Create или изоляцию квоты.
5. Проверить архив закрытых входящих по ops/OWNER-TASKS.md: полный перенос до удаления, сохранность ID/результатов, отсутствие активных задач в удаляемой части. Проверить иные журналы по штатной недельной процедуре. Не создавать пустой архив для видимости выполненной чистки.
6. Исправления — в разрешённом объёме, под соответствующим замком/CAS; после инструкций cert_github.py, нужные тесты, validate_site.py, canon_health.py, D7 и readback. Снимок до миграции сертификата — archive/ops/instruction-certificate-legacy-2026-10-26.json, история, не authority.

Шаблоны Project Instructions — USER-GUIDE.md. Их обновление в GitHub не доказывает замену текста в настройках ChatGPT/Claude Project: проверять этот слой отдельно при доступном интерфейсе, иначе явно отмечать непроверенным. Обычное отсутствие доступа к настройкам не блокирует работу по свежему main.

## Продолжение после смены чата (27.10.2026; дополнено 31.10.2026)

В недельной сверке выполнить `python3 scripts/continue_preflight.py . --require-short`: проверить фокус, связанный раздел и доказательства; не менять фокус из-за времени фоновой проверки. При изменении результатов сначала сверить канон, затем обновить recovery и пакет по `ops/CONTINUE-PROTOCOL.md`. Недельная чистка сохраняет связанные разделы незавершённых задач. Настройка Project и факт исполнения нового чата проверяются раздельно. Для очереди запуска дополнительно проверить `foreground_owners.<surface>.session_id/epoch` и историю передачи по `ops/LAUNCHER-COORDINATION.md`: старый интерактивный чат не сохраняет право писать после передачи, независимые scheduled peers не отключаются и claims не сбрасываются.

## Продолжай: все проекты и квитанции · 27.10.2026

При недельной проверке для каждого ID из projects/projects.json выполнить continue_preflight с --project ID, проверить собственный фокус/idle и SHA доказательств, ссылки пакета и журнал приёма. Проверить, что receipt содержит реальный чат/явную недоступность ID, результаты семи проверок и первое фактическое действие; отсутствие квитанции не исправлять выдуманной записью. Живой журнал ограничивается 20 при каждой записи, старые сохраняются целиком в проектном archive/reports/handoff-receipts.json; проверить отсутствие конфликтов ID/потери истории. Проверка реальным следующим новым чатом остаётся открытой до его собственной квитанции. Паузы/очереди не менять из-за готовности пакета.
