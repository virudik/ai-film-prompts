# Сверка инструкций и автоматизаций

Статус: действует. Проверено: 19.11.2026.

Сверку делает ChatGPT в существующем недельном цикле (воскресенье 08:55 МСК), после изменения общих правил и при обнаруженном противоречии. Новых расписаний нет. Порядок чистки — NEW-CHAT-HANDOFF.md. Данные и творческие решения не меняются ради прохождения проверки.

1. Прочитать свежие main: семь инструкций, CLAUDE.md, ops/OWNER-TASKS.md, ops/CANON-LOCK.md, ops/TOPVIEW-EVENT-WAKE.md, ops/LAUNCHER-COORDINATION.md, ops/PRIMARY-BACKUP-WAKE.md, ops/TOPVIEW-RETRY.md, ops/slot-backup.json, очередь/manifest, ops/relay-wake.json, ops/claude-wake.json и automation-monitor-status.json. Правило живёт в профильном документе; остальные тексты ссылаются на него. Сверить полномочия, исключения замка, трёхчасовой порог, ответ в тот же тред и сроки архивирования. Не переносить исторические зависимости сцен в действующий prompt.
2. Сверить живые задания с `ops/PRIMARY-BACKUP-WAKE.md`. Идентификаторы брать из `ops/slot-backup.json` и `ops/relay-wake.json`, в этот документ их не копировать. Проверить полный prompt, enabled, расписание и подписку Relay. Включённая событийная рутина Grok — ожидаемое состояние резерва, а не ошибка. Недоступный источник = not_checked с причиной, а не подтверждение. Не изменять расписания и подписку при обычной правке prompt; при webhook-update передать полный существующий набор triggers. После изменения снова прочитать и сравнить точный текст.
3. Выполнить `python3 scripts/check_instruction_consistency.py .`. Прежний `--automations` проверяет legacy-пару Work; для действующих Dot заданий отдельно передать `--dot-automations` с локальным временным JSON: `source="automations.get"`, фактический `checked_at` UTC, `automations` (id, prompt, schedule, default_timezone, is_enabled, updated_at). Снимок не старше часа. ID читаются из `ops/slot-backup.json` и `ops/relay-wake.json`. Read-only проверка не меняет настройки и не требует изменения расписаний. Отдельно проверяются выбранные prompt-инварианты, enabled и расписание. Для подписки нужны `relay_subscriptions` с доказанной привязкой `automation_id`, event, arguments, active; общая активная подписка коннектора такую привязку не доказывает. При отсутствии её источника `subscription_status=not_checked`, результат Dot `partial`, не полный pass. Без свежего снимка `dot_current_tasks.status=not_checked`. `runtime_status=not_checked` всегда: этот checker не доказывает выполнение, доставку, Create или художественную приёмку. Полные prompts и результаты запусков не сохранять в git; `--write` сохраняет только компактный отчёт, исторический JSON без свежих данных не переписывать.
4. Скрипт покрывает выбранные инварианты, не всё значение текста. Прогон `reports/instruction-consistency.json` от 17.11.2026 19:05 МСК (`checked_at` 2026-11-17T16:05:16Z, статус warn, проблема `relay-subscription`) сверял сертификат байтов, часовое задание и Relay. Он не проверял порядок t601u против запрета t512u, закрытие PR 369/370/371/640, влитие PR 516 и 518 и источник запуска по квитанции, а не по префиксу имени. Возврат этих формулировок ловят коды `stale-phrase:*` в `scripts/check_instruction_consistency.py`. Этот исторический JSON не переписывается прогоном без свежего снимка автоматизаций. Агент отдельно сопоставляет текущие зависимости/приоритеты очереди, границы полномочий и противоречащие формулировки; фиксирует результат и непроверенное в checkpoint. Сертификат 7/7 подтверждает байты, enabled/подписка — настройку; успех выполнения подтверждают собственные run/task receipts. Сверять независимый подхват обоих исполнителей, точный уникальный holder/lease, одноразовый submitting intent, запрет повторного unknown Create и передачу foreground ответственности по «Продолжай». Порядок пробуждения задаёт `ops/PRIMARY-BACKUP-WAKE.md` (Dot основной, Grok резерв), а не прежнее предпочтение ordinary/Work. При исчерпании лимита Work отдельное правило `ops/CONTINUE-PROTOCOL.md`: обычный ChatGPT сначала пытается запускать сам; если не может — запускает Grok Bot (резерв). Порядок пробуждения при этом остаётся Dot основной, Grok резерв. GET-скан и запуск задания не доказывают GUI Create или изоляцию квоты.
5. Проверить архив закрытых входящих по ops/OWNER-TASKS.md: полный перенос до удаления, сохранность ID/результатов, отсутствие активных задач в удаляемой части. Проверить иные журналы по штатной недельной процедуре. Не создавать пустой архив для видимости выполненной чистки.
6. Исправления — в разрешённом объёме, под соответствующим замком/CAS; после инструкций cert_github.py, нужные тесты, validate_site.py, canon_health.py, D7 и readback. Снимок до миграции сертификата — archive/ops/instruction-certificate-legacy-2026-10-26.json, история, не authority.

Шаблоны Project Instructions — USER-GUIDE.md. Их обновление в GitHub не доказывает замену текста в настройках ChatGPT/Claude Project: проверять этот слой отдельно при доступном интерфейсе, иначе явно отмечать непроверенным. Обычное отсутствие доступа к настройкам не блокирует работу по свежему main.

## Продолжение после смены чата (27.10.2026; дополнено 31.10.2026)

В недельной сверке выполнить `python3 scripts/continue_preflight.py . --require-short`: проверить фокус, связанный раздел и доказательства; не менять фокус из-за времени фоновой проверки. При изменении результатов сначала сверить канон, затем обновить recovery и пакет по `ops/CONTINUE-PROTOCOL.md`. Недельная чистка сохраняет связанные разделы незавершённых задач. Настройка Project и факт исполнения нового чата проверяются раздельно. Для очереди запуска дополнительно проверить `foreground_owners.<surface>.session_id/epoch` и историю передачи по `ops/LAUNCHER-COORDINATION.md`: старый интерактивный чат не сохраняет право писать после передачи, независимые scheduled peers не отключаются и claims не сбрасываются.

## Продолжай: все проекты и квитанции · 27.10.2026

При недельной проверке для каждого ID из projects/projects.json выполнить continue_preflight с --project ID, проверить собственный фокус/idle и SHA доказательств, ссылки пакета и журнал приёма. Проверить, что receipt содержит реальный чат/явную недоступность ID, результаты семи проверок и первое фактическое действие; отсутствие квитанции не исправлять выдуманной записью. Живой журнал ограничивается 20 при каждой записи, старые сохраняются целиком в проектном archive/reports/handoff-receipts.json; проверить отсутствие конфликтов ID/потери истории. Проверка реальным следующим новым чатом остаётся открытой до его собственной квитанции. Паузы/очереди не менять из-за готовности пакета.

## Общая работа с Grok · 16.11.2026

Проверить, что adapter публикует очередь и журнал запуска одним коммитом, сохраняет исходные идентификаторы сообщений и не сбрасывает учёт после неизвестного исхода.
