# Topview: референсы и бесплатный веб-запуск

Практический порядок для сменщика, проверен на шести запусках Scene 28 14–15.10.2026. Это дополнение к `SYNC-RUNBOOK.md`, не восьмая инструкция и не отдельный установленный skill. Канон — свежий GitHub main. Доказательства: `reports/scene28-launch-2026-10-15.json` и `reports/evidence/scene28-six-slots-2026-10-15.jpg`.

## 1. Подготовить референсы автоматически

1. По команде создания/запуска прочитать точный автономный промт master и manifest сцены. Составить локальный порядок @ImageN / @VideoN: identity, location, prop, continuity, pose. Проверить существование и SHA256 каждого файла.
2. Использовать существующие точные листы персонажей и локации. Дополнительный helper нужен только для конкретной проблемы позы/геометрии; не генерировать его ради количества. Листы identity приоритетнее групповых композиций.
3. Если действительно нужен новый AI-кадр — создать его штатным генератором изображений ChatGPT с исходными референсами либо через подтверждённо бесплатный сайт Topview. Платный Topview MCP/Canvas запрещён. Каждый кадр отдельно визуально проверить и сохранить до следующего: `references/scenes/scene-N/`, manifest с происхождением/SHA/QC, миниатюра/ссылка по runbook. QC ассистента не означает approval владельца.
4. Настоящий монтажный кадр не заменять выдуманным AI-изображением. Для C28 извлечь чистый кадр результата части 2; для сцен 36/37 нужны реальные видеовходы, перечисленные в отчёте `reports/reference-readiness-2026-10-15.md`.

## 2. Отправить видео через сайт

1. Проверить разрешение владельца, свежие решения/статусы, отсутствие уже отправленного того же промта и глобальные физические слоты аккаунта. Шесть активных задач = шесть занятых слотов, даже если Scene ID один. Читать Topview через MCP допустимо; генерацию через MCP/Canvas не отправлять.
2. Открыть доску AI Film через доступный разрешённый браузер под входом владельца. В ChatGPT Work веб-запуск подтверждён 14–15.10; браузер Claude — не единственный вариант. Наличие входа в одной сессии не доказывает его наличие в новой или фоновой. Дождаться загрузки интерфейса: краткая надпись Login до гидратации сама по себе не доказывает выход из аккаунта.
3. Выбрать модель, длительность, 16:9, количество 1 и «Безлимитный режим — бесплатно». Проверить цену непосредственно перед отправкой. На шести проверенных запусках бесплатное разрешение было **720p**, `useUnlimitMode=true`, `creditsCost=0`; 1080p в тексте master не является фактической настройкой. Не переключаться на платные 1080p и не переписывать master ради UI. Если бесплатный режим недоступен — остановить отправку и сообщить.
4. Импортировать полные файлы в точном порядке manifest; дождаться завершения всех загрузок. В Work использовать документированный file chooser/shared-files API браузера. Старый Claude-specific обход через JS не переносить в другую среду вопреки её инструментальным правилам. Не загружать миниатюры вместо исходников.
5. Вставить полный промт из master после загрузок. Перечитать форму: число/порядок изображений, вся длина и конец текста, модель/длительность/разрешение/формат/режим/цена. Chips @ImageN могут нормализовать пробелы; сравнивать весь текст через `scripts/topview_prompt_match.py`, не только начало. Дать UI завершить обновление перед снимком/кликом.
6. Нажать «Создать» **один раз**. При задержке/ошибке интерфейса сначала искать новую задачу, а не нажимать повторно. По фактическому task ID прочитать параметры: модель, 30/15с, 720p, 16:9, входы, unlimited и стоимость. Полное нормализованное совпадение промта должно быть однозначным.
7. Сохранить receipt с task ID, временем, параметрами, хешем промта, порядком входов и снимком UI; обновить тот же checkpoint/register. «Запущено» говорить только после подтверждения задачи. Штатный робот сам обновляет телеметрию; вручную не подделывать heartbeat, approval и slow.

## 3. Один запуск при освобождении слота

Прямая команда владельца 15.10.2026 разрешает один следующий запуск. Выбран **Scene 28 / B6**: Маша, Лёша и Виталик; Wan 3.0, 30с, 720p, 16:9, количество 1, максимум 0 кредитов. Полный пакет/хеши: `ops/pending-topview-launch.json`. Ожидание слота не означает отправку.

Фоновая проверка использует одну существующую задачу ChatGPT `6acae6ab433481919e88665c520b8ef2`, переименованную под B6, не дублирует старые архивные watchers. Фактическое включение проверять через Automations; запись в GitHub сама по себе расписание не создаёт. Проверка — не чаще раза в час. GitHub-робот остаётся писателем телеметрии, его GET-сканер видео не запускает.

- Перед отправкой заново проверить live очередь (все доски аккаунта), owner decisions, exact B6 prompt/hash и четыре входа, а также все новые задачи с момента разрешения. При изменившемся промте/референсе или отмене владельца — остановиться, не подменять кандидата.
- Перед GUI-submit атомарным GitHub compare-and-swap перевести reservation из `waiting_for_slot` в `claimed`, указав уникальный run ID и UTC. Другой агент при `claimed`/`submitted` не отправляет. Это координационная защита агентов, не серверный idempotency key Topview.
- После единственной отправки записать `submitted`, task ID и проверенный receipt, выключить эту automation. При сомнительном результате оставить `submission_unknown` и сначала восстановить task ID; слепых повторов и автоматического перезапуска failed-видео нет.
- Если слот есть, но фоновому заданию недоступны браузер/вход/загрузка, записать `blocked_browser`, уведомить владельца и выключить повторные проверки. Продолжить в рабочем чате с тем же разрешением; платный API не использовать. Нельзя обещать гарантированный фоновый GUI-submit до проверки реальных возможностей запуска.
- Если слот занят — ничего не отправлять, не переписывать телеметрию и не слать каждый час одинаковое сообщение. Не выдавать ETA за обещание освобождения.
