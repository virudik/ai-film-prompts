# Повторы после подтверждённой технической ошибки

Статус: действует. Проверено: 16.11.2026.

Решение владельца 16.11.2026 (t634s3201), уточнение t635u. Это единственное место правила повторов. Остальные инструкции только ссылаются сюда. Очередь этим файлом не меняется.

- Неоднозначную или неизвестную отправку не повторять никогда: только сверка.
- До двух дополнительных попыток допустимы только после подтверждённой технической ошибки Topview и только если у этого пункта нет отдельного запрета. Запрет пункта в живой очереди важнее общего лимита: `automatic_retry: false`, явная запись «один Create» или иной запрет повтора. Такой запрет уже стоит, в частности, на диалогах сцены 89. Содержательный отказ, включая модерацию, copyright и код провайдера 7000, автоматически не повторять.
- Лимит «не больше двух» — живое поле `retry_policy.max_retry_attempts_per_item` в `ops/topview-launch-queue.json`. Поле этим файлом не переписывалось.
- Один Create на попытку.
- Историю и подтверждения всех попыток сохранять: прежние task id, claim, intent и receipt не стирать и не переиспользовать. Каждая разрешённая новая попытка проходит тот же протокол со своими новыми claim и intent (`ops/LAUNCHER-COORDINATION.md`; обёртка `scripts/launcher_entry.py`, `ops/LAUNCHER-ENTRY.md`).
- Только бесплатный Unlimited за 0 кредитов.
- Техническая переделка, которую владелец явно поручил новым item id с суффиксом `-R2`, — новый пункт, не повтор той же попытки.
