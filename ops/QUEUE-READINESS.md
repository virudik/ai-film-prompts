# Очередь, контрольный отпечаток и свежесть

Решение владельца23.10.2026: различать состояния каждой части и поддерживать их роботом. Канон — GitHub main; новые расписания не нужны.

## Очередь

`scripts/queue_readiness.py` строит `ops/queue-readiness.json` из точной очереди, наличия/SHA файлов, подтверждённых приватных входов и task-map/Topview. Его вызывают существующие `sync-from-drive.yml` и `robot_telemetry.py` после обработки новых результатов. Это производный отчёт, не новая очередь и не разрешение на запуск. SHA очереди связывает отчёт с точной редакцией; сайт не применяет отчёт к другой версии очереди.

- **Готова по входам, ждёт свободный слот:** необходимые входы записаны и доступны. Перед отправкой всё равно нужны свежий слот, действующее разрешение, точный промт, материализация приватных файлов с SHA/QC и веб-режим Unlimited0.
- **Ждёт результат конкретной части:** необходимого исходного результата ещё нет. Если источник ещё не отправлен, это явно указано.
- **Результат получен — подготовить и проверить стык:** `success` подтверждён, но вырезка/кадр и QC ещё не записаны. Это не «ждёт генерацию» и не READY.
- **Нужен референс / проверка файла:** нет самостоятельного изображения или не совпадает SHA. Это не автоматически зависимость от прошлой сцены.
- **Решение владельца / оценка / подготовка промта:** отдельные ограничения; наличие картинок их не снимает.

Сайт показывает отдельную строку на каждую часть. Существующий робот поддерживает отчёт автоматически, но не изображает художественную проверку и не делает автоматическую приёмку. Подготовку и визуальный QC стыка выполняет агент. Уже отправленные попытки не переписываются. При свободном слоте пропускать заблокированные пункты и брать следующий разрешённый готовый по текущему priority.

## Откуда контрольный отпечаток

GitHub main публикуется в GitHub Pages. `project-status.json` вычисляется валидатором из master и сертификата семи инструкций; SHA256 проверяется страницей по реально загруженным байтам `video-prompts.md`. `topview-status.json.checked_at` — время реальной проверки Topview; `automation-monitor-status.json` — подтверждённый результат цикла; `ci-status.json` — GitHub Actions. Drive, Notion и текст старого чата не обновляют канон.

Открытая страница перечитывает master/status/сертификат/телеметрию каждые5минут, при возвращении на вкладку и восстановлении сети. Возраст данных пересчитывается каждую минуту. Если опубликована новая версия master, отпечаток сверяется с ней, а страница предлагает обновить сцены после сохранения черновиков: промты, прокрутка и комментарии насильно не перерисовываются. SHA показанной старой версии явно отделён от SHA новой публикации.

Робот опрашивает Topview по существующему расписанию каждые10минут; изменения публикует сразу, неизменившийся снимок — пульсом через50минут. Сайт предупреждает при возрасте проверки больше120минут. Self-heal и резервный монитор остаются действующими. Нельзя обновлять checked_at без реального наблюдения, выключать предупреждение или путать время чтения страницы со временем Topview. Ошибка сети сохраняет последний подтверждённый снимок с предупреждением.
