# План: синхронизация с Drive без компьютера владельца (НЕ КАНОН, рабочий план)

Решение владельца 10.10.2026: сделать так, чтобы мониторам (Claude и ChatGPT) и рабочим чатам не нужен был включённый компьютер владельца для правки master и инструкций на Drive.

## Почему сейчас нужен компьютер
- Коннектор Google Drive у Claude читает файлы, а менять их содержимое не умеет (только название и папку). Поэтому Claude пишет master и инструкции через диск `J:` на компьютере владельца (Google Drive для компьютера).
- Монитор Claude — облачная scheduled task. В приложении у неё отмечено «Требуется этот компьютер (Vint)», но запуск 10.10 20:10 доступа к `J:` не получил (`degraded`), а в API у задачи нет `bound_device`. Кроме того, Google Drive на компьютере выгружает файлы с задержкой до 35 минут, а один раз запись большого файла через мост оборвалась (61 КБ из 592 КБ).
- ChatGPT компьютер не нужен: его коннектор Drive умеет перезаписывать файл по тому же ID.

## Решение
GitHub сам пишет в Drive через сервисный аккаунт Google — отдельного «бота» с доступом **только** к папке `AI Film Prompts Master`.
- Агент готовит правку как раньше (fresh-read Drive → минимальная правка → валидатор) и вместо `J:` коммитит запрос: `python3 scripts/drive_write_request.py . --file-id … --name … --base <свежие байты Drive> --new <правка> --by … --reason … [--sync]`.
- Workflow `.github/workflows/drive-write.yml` (`scripts/drive_write.py`):
  1. ещё раз читает файл на Drive;
  2. если байты уже не те, с которых делалась правка, — **отказ**, ничего не перетирается;
  3. иначе записывает в тот же ID;
  4. скачивает обратно и сверяет байт в байт;
  5. пишет результат в `drive-write-results/` и запускает синхронизацию master.
- Не создаёт файлов, не меняет доступы, ничего не удаляет. Без ключа только сообщает `not_configured`.
- Монитор, ChatGPT и рабочий чат пользуются одним путём; `J:` остаётся запасным.

## Что нужно от владельца (один раз, ~10 минут)
1. Открыть https://console.cloud.google.com под своим аккаунтом Google → создать проект (например, `ai-film-sync`).
2. «APIs & Services» → «Enable APIs» → включить **Google Drive API**.
3. «IAM & Admin» → «Service accounts» → «Create service account» (имя, например, `ai-film-writer`), роли не нужны → «Done».
4. Открыть созданный аккаунт → «Keys» → «Add key» → «Create new key» → JSON. Скачается файл с ключом. **Никому его не пересылать, в чат не вставлять.**
5. В Google Drive открыть доступ к папке `AI Film Prompts Master` для почты сервисного аккаунта (вида `ai-film-writer@ai-film-sync.iam.gserviceaccount.com`) с ролью «Редактор». Папка от этого публичнее не становится: доступ получает только этот бот.
6. GitHub → репозиторий `virudik/ai-film-prompts` → Settings → Secrets and variables → Actions → «New repository secret»: имя `GDRIVE_SA_KEY`, значение — всё содержимое JSON-файла.
7. Написать агенту «ключ добавлен».

## Что сделает агент после «ключ добавлен»
1. **Пробная запись.** Тот же ID, те же байты (безопасно) для файла `CHATGPT-TASK-2026-10-10-from-Claude.md` → в результате должно быть `applied (idempotent)`.
2. **Первая боевая правка** через workflow, с read-back.
3. **Переключить процедуры** на путь «запрос в GitHub»: `ops/CLAUDE-MONITOR.md`, задача ChatGPT и канон (handoff, SYNC-RUNBOOK, USER-GUIDE) по обычному циклу. `J:` остаётся запасным путём.
4. **Убрать у монитора Claude зависимость от компьютера** в процедуре.

## Риски и правила
- Ключ хранится только в GitHub Secrets. Если он утечёт — удалить ключ в Google Cloud и создать новый.
- Защита от гонок: запись отклоняется, если Drive изменился после подготовки правки. Один писатель сохраняется (`monitor-role.json`).
- Генерации, approve, удаление — по-прежнему только по решению владельца.
