# ChatGPT hourly monitor — короткий безопасный цикл (временный: продлён владельцем 13.10.2026 до перехода телеметрии на GitHub-робота)

Статус: действует (резервный протокол ChatGPT; основной писатель телеметрии — GitHub-робот). Проверено: 18.10.2026.

**Источник истины:** GitHub `virudik/ai-film-prompts:main`. **Это дополнение, не замена 7 инструкций и NEW-CHAT-HANDOFF.md.** Писатель только назначенный в `monitor-role.json`; 16.10.2026 07:00 МСК больше НЕ конец: владелец 13.10.2026 продлил роль писателя ChatGPT до принятия GitHub-робота (`ops/ROBOT-TELEMETRY.md`); когда `monitor-role.json` назначит основным `robot`, ChatGPT сам перейдёт в read-only. Не включать архивные мониторы.

## Каждый час HH:55 МСК (приоритет — проверяемый результат)
1. Зафиксируй фактическое начало. Прочитай live `monitor-role.json`, `automation-monitor-status.json`, `topview-status.json`, `topview-task-map.json`, `topview-checkpoint.json`, `project-status.json` и верхний handoff. Проверку семи полных инструкций и 500KB master делай при изменившихся хешах, необходимости материальной правки или ежедневном аудите; не позволяй большому контексту сорвать ежечасную легкую проверку.
2. Выполни `scripts/monitor_role.py . --me chatgpt --dry-run` или эквивалент по свежему GitHub main, с 50-минутной защитой **по защищённым файлам другого агента**, не по коммитам теневого GitHub-робота. При `skip` ничего не коммитить и не имитировать heartbeat.
3. При `run`: read-only Topview owned boards (или счётчики 11 досок из независимого GitHub shadow **только как дополнительное свидетельство**) + первая страница задач AI Film + прямые сведения обо всех известных active task ID. 5–6 прямых запросов можно параллельно. Кратковременный отказ одной задачи не должен останавливать **диагностическую запись**. Если данные неполные — `health=degraded`; не менять topview-status.checked_at и слот-счётчики на неподтверждённых данных.
4. **Запиши в GitHub `automation-monitor-status.json` по итогам КАЖДОГО допущенного запуска**, даже если `degraded`: `last_scheduled_cycle.started_at`, `completed_at` (реальные UTC), `runner=chatgpt_scheduled_task`, `health`, `phases_completed`, `phases_missing` и конкретную причину. `last_successful_by_runner.chatgpt` обновить только при полностью завершённом, проверенном цикле. `scripts/monitor_status.py` вызывается **с `--runner chatgpt`**. Отсутствие нового коммита ≠ успех.
5. Если получены полные достоверные данные, в минимальном diff обнови `topview-status.json`, `topview-task-map.json`, journal, при необходимости master + `SYNC-TRIGGER.txt`; пересобери `project-status.json` (`health=ok`) и проверь GitHub Pages; `topview-checkpoint.json` — **ПОСЛЕДНИМ** после read-back. Конфликт GitHub push: fresh-fetch/recompute, не replay старых данных. Не создавай Scene ID автоматически.
6. Topview `success`/`failed`/`cancelled` влияет только на техническую очередь и свободные физические слоты. **НИКОГДА не снимай canonical slow** без реального нажатия кнопки владельца, подтвержденного Supabase `owner_decisions` и GitHub read-back. «Не ждать» не отменяет Topview-задачу и не освобождает физический слот; технический success ≠ approval. Никаких генераций, платных действий, rerun, удаления, редактирования промтов из `reports/prompt-audit-2026-10.md`.
7. Не переименовывать ручной `manual_interactive_verification` в `last_scheduled_cycle`. Честная ошибка `degraded` лучше молчаливого таймаута. Если GitHub запись в scheduled-контексте **недоступна**, сообщить владельцу как проблему платформенного доступа: задача может запускаться без полномочий записи; нет права выставлять ложную зелёную отметку.

**Доказательство восстановления:** новая запись `last_scheduled_cycle` с `runner=chatgpt_scheduled_task` из реального запуска, валидные фазы, read-back GitHub main + CI/Pages. До такого подтверждения фоновый монитор считать `degraded`, независимо от ручной проверки или успешного теневого Topview-робота.
