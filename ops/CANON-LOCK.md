# Замок канона — кто сейчас пишет (решение владельца 17.10.2026)

Статус: действует. Проверено: 26.10.2026.

Файл `ops/canon-lock.json` показывает, кто прямо сейчас правит канон. Он заменяет устное «канон занят / канон свободен» между ChatGPT и тредами Claude. Писать может любой агент (ChatGPT или Claude): кому владелец поручил задачу, тот её и делает. Замок только не даёт двоим работать над каноном одновременно.

**Канон** здесь — всё, что правят агенты: `video-prompts.md`, 7 инструкций, `ops/topview-launch-queue.json`, `references/`, `reports/current-work-checkpoint.md`, `work-resume-register.json`, квитанции.

**Не берут замок:** GitHub-робот (телеметрия и статусы, `topview-robot.yml`), робот кнопок владельца (`sync-from-drive.yml`) и другие workflow `github-actions[bot]`. Они пишут только свои файлы.

**Робот кнопок очереди (с 18.10.2026)** меняет `ops/topview-launch-queue.json` (кнопки сайта ▲ ▼ ✕ «в очередь») только когда замок свободен; при занятом замке ждёт и пишет владельцу на сайте «Ждёт: канон занят (кто) до …». Сам замок он не берёт: его правка — один маленький коммит с CAS-push. Входящие задачи `ops/owner-tasks.json`, их архив `archive/ops/owner-tasks-archive.json` (появится при первом переносе) и отметки референсов `references/reference-review.json` — не канон: их пишут робот и агенты без замка (порядок — `ops/OWNER-TASKS.md`).

## Формат

```json
{"schema_version": 1, "state": "held", "holder": "chatgpt", "task": "запуск S45-R1",
 "acquired_at": "2026-10-17T18:00:00Z", "expires_at": "2026-10-17T18:45:00Z", "released_at": null,
 "rules": "ops/CANON-LOCK.md"}
```

`holder`: `chatgpt` или `claude:<короткое имя треда>`. Время — UTC.

**Канон свободен**, если файла нет, `state` = `free` или `expires_at` уже прошло.

## Порядок для любого писателя

1. Свежий `main`. Прочитать `ops/canon-lock.json`.
2. Занят другим и не просрочен — канон не править. Делать то, что не пишет в канон (чтение, проверки, подготовка в черновике), или подождать. Ничего не ломать и не перехватывать.
3. Свободен — отдельным маленьким коммитом записать `state: held`, свой `holder`, задачу и `expires_at` = сейчас + до 45 минут (не больше 120). Отклонённый push = кто-то успел первым: перечитать замок и начать с шага 1.
4. Работать как обычно: свежий pull → минимальный diff → push. Если работа длиннее — продлить `expires_at` тем же коммитом с правкой или отдельным.
5. Последним коммитом работы (или вместе с ним) записать `state: free`, `released_at`, `expires_at: null`.
6. Сбой посреди работы — замок сам освободится в `expires_at`. Чужой непросроченный замок не снимать.

Замок — договорённость, а не запрет git: если кто-то его не проверил, git всё равно отклонит устаревший push. Правила fresh-read, минимального diff и «отклонённый push = перечитать и повторить с нуля» остаются.

Треды Claude могут пользоваться скриптом:

```
python3 scripts/canon_lock.py . status
python3 scripts/canon_lock.py . acquire --holder claude:<тред> --task "…" --minutes 45 --push
python3 scripts/canon_lock.py . release --holder claude:<тред> --push
```

ChatGPT правит JSON напрямую через коннектор GitHub по тем же шагам.

## Замок проекта (20.10.2026)

У каждого проекта кроме Серёгиуса свой замок `projects/<id>/canon-lock.json` (тот же формат). Он нужен для правок **только внутри** `projects/<id>/`; всё остальное (корень = Серёгиус, 7 инструкций, сайт, скрипты, workflow, реестр `projects/projects.json`) — под общим замком `ops/canon-lock.json`. Разные замки можно держать параллельно: Claude в Котмонавтах и ChatGPT в Серёгиусе не мешают друг другу. Команда: `python3 scripts/canon_lock.py . acquire --project <id> --holder … --task "…" --push` (так же `release --project <id>`). Правила проектов — `projects/README.md`.

## Автоматика ChatGPT

Часовой цикл `6acae6ab433481919e88665c520b8ef2` (HH:55 МСК) и Relay-обработчик перед канонической записью/запуском проверяют замок. Чужой действующий замок запрещает каноническую запись и Topview Create; чтение и явные исключения входящих/отметок выше доступны. При свободном замке и реальном изменении взять его и освободить последним коммитом с данными. Обычный цикл без изменений — без замка и коммита (владелец 23.10).

**Новый подтверждённый Relay event_id — изменение учёта**, даже при `outcome=no_update`: квитанция по `ops/TOPVIEW-EVENT-WAKE.md` обязательна под собственным замком/CAS с readback. Завершённый дубликат — без новой записи. Чужой замок — `blocked_lock/receipt_not_saved`, без ложного ACK. Квитанция не разрешает генерацию. Тот же порядок действует в рабочем чате; не имитировать событийные ACK интерактивно.

**Квитанция настоящего часового вызова (31.10.2026, исправление простоя по поручению владельца)** — тоже изменение учёта: существующий исполнитель HH:55 сохраняет компактные начало и фактический итог в `reports/topview-launcher-cycle.json` по `ops/TOPVIEW-EVENT-WAKE.md`, под собственным замком/CAS/readback. Это уточнение к обычному циклу без изменений: отсутствие нового видео не отменяет след реального вызова. Чужой замок или недоступная запись — явный `receipt_not_saved`; интерактивный чат не имитирует часовую квитанцию. Сохраняется одна текущая запись без длинного добавления истории в checkpoint на каждом цикле.
