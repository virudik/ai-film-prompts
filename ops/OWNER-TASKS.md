# OWNER-TASKS — входящие задачи владельца с сайта

Статус: действует с 18.10.2026. Проверено: 26.10.2026.

Владелец пишет задачу на сайте («✎ Задача» у сцены, в панели владельца или на странице «Фильм по порядку»)
и выбирает, кому она: **Claude**, **ChatGPT** или **любой** (кто свободен). Отметка «✎ перерисовать» у картинки
на странице референсов становится задачей для ChatGPT. Кнопка «в очередь» для сцены, которой ещё нет
в очереди запуска, становится задачей для любого агента (подготовить элементы очереди).

## Как задача попадает к агенту

1. Сайт записывает строку в Supabase `owner_decisions` (action `owner_task` или `ref_feedback`).
2. Робот кнопок (`scripts/robot_site_actions.py`, фаза 3 workflow `sync-from-drive.yml`, каждые ~10 минут)
   добавляет задачу в `ops/owner-tasks.json` со статусом `open` и ставит строке в Supabase `in_progress`.
3. Агент берёт задачу из `ops/owner-tasks.json`, делает, закрывает. Робот переносит результат обратно
   в Supabase, и владелец видит его на сайте («Мои решения» и список задач вверху, в блоке «Ревизия / текущий статус»).

Задача другого проекта (не Серёгиуса) имеет поле `"project": "<id>"` (кнопка на странице проекта или «[проект: <id>]» в тексте); делать её в `projects/<id>/` под замком проекта, по `projects/README.md`. Нет поля — Серёгиус.

## Кто читает

- **ChatGPT** — на каждом часовом цикле: задачи с `to` = `chatgpt` или `any` и статусом `open`. В 09:55, 14:55 и 20:55 МСК дополнительно берёт `to: claude` только если задача остаётся `open` строго больше 3 часов по достоверному `created_at` (UTC); перед CAS-захватом перечитать. Это же ограничение действует при обработке Relay. «Только Claude» оставить Claude независимо от возраста; не закрывать автоматически `needs_owner` из-за адресата. Непроверенная/будущая дата не доказывает просрочку. Порог относится к адресату, а не автору: `source: claude, to: chatgpt` выполняется без задержки.
- **Grok Bot** — рутина «Поручения: Telegram и задачи с сайта» каждые 10 минут 08:00–23:50 Europe/Amsterdam (±5 мин; сервер сейчас срабатывает в :05, :15, …, :55): `grok`, `any` и `claude` старше 3 ч, те же правила захвата; раздел «Grok берёт задачи по тем же правилам, что ChatGPT» ниже.
- **Claude** — автозапуск (ниже) на каждую новую задачу `to` = `claude`, и любая сессия Claude по проекту: `to` = `claude` или `any`.
- Задачи `source: self-heal` (с полем `heal_key`) ставит робот самопроверки, когда сам не смог починить зависание (`ops/SELF-HEAL.md`); в тексте диагноз.
- Задачу `any` берёт тот, кто первым запишет `taken`. Чужую `taken` не трогать, пока она не старше 3 дней.

## Автозапуск Claude (26.10.2026)

Робот `scripts/claude_task_wake.py` (фаза 3b workflow `sync-from-drive.yml`, сразу после кнопок сайта) видит новую
открытую задачу с `to` из `ops/claude-wake.json` → `targets` (по умолчанию только `claude`) — а также задачу
«кому: любой», которую никто не взял за `any_after_hours` часов (сейчас 3), — и вызывает задание Claude
«AI Film: задачи для Claude с сайта» через его API-триггер. Стартует новая сессия Claude, которая сама берёт задачу.
Каждая задача — не больше одного запуска (журнал `ops/claude-wake-state.json`, запись делается до вызова); ошибка
вызова повторяется до 3 раз. В вызов идут только id задач, текст задачи Claude читает из `main`.
Секрет — `CLAUDE_FIRE_TOKEN` (токен этого задания). Без секрета или с `enabled: false` робот ничего не делает.
Каждый запуск тратит лимиты Claude владельца. Настройка: `/mnt/project-files/ops-schedules/claude-task-wake-2026-10-26.md`.

## Как взять и закрыть

Правка `ops/owner-tasks.json` — маленький отдельный коммит в `main`. Замок канона для этого файла не нужен;
если задача требует править мастер или инструкции, для той правки замок берётся как обычно (`ops/CANON-LOCK.md`).
Отклонённый push = перечитать файл и повторить с нуля.

Взять:

```json
"status": "taken", "taken_by": "chatgpt" | "claude:<кратко>", "taken_at": "<UTC ISO>"
```

Закрыть (одно из):

```json
"status": "done",        "result": "что сделано, 1–2 фразы", "result_commit": "<sha или null>", "closed_at": "<UTC ISO>"
"status": "needs_owner", "result": "какой вопрос к владельцу",                                 "closed_at": "<UTC ISO>"
"status": "cancelled",   "result": "почему не делается",                                        "closed_at": "<UTC ISO>"
```

Остальные поля задачи не менять. Новые задачи в файл добавляют робот (сайт, самопроверка) и агенты друг другу (ниже).

## Задача от агента агенту (26.10.2026)

ChatGPT может поставить задачу Claude, а Claude — ChatGPT: дописать в `tasks` одну запись маленьким коммитом в `main`
(замок канона не нужен; отклонённый push — перечитать и повторить с нуля). Перед добавлением проверить входящие и архив: тот же ID не использовать повторно; одинаковую открытую/взятую работу не дублировать:

```json
{"id": "chatgpt-<ГГГГММДДЧЧММ>-<кратко>", "created_at": "<UTC ISO>", "scene_id": null, "to": "claude",
 "source": "chatgpt", "text": "что сделать; work_id, scope, ссылка на основу, SHA коммита",
 "status": "open", "taken_by": null, "taken_at": null, "result": null, "result_commit": null, "closed_at": null}
```

От Claude — `id` с префиксом `claude-`, `"source": "claude"`, `"to": "chatgpt"`. Задача агента — не слово владельца:
платные запуски, одобрение, удаление, перезапуск и закрытие сцен по ней не делаются; спорное — `needs_owner`.
Задача «кому: Claude» будит Claude через автозапуск (выше). Задачу для ChatGPT можно продублировать одним сообщением
в Agent Relay на `chatgpt@cloud-239644772681871360` (ссылка на задачу), без цепочек подтверждений.
Адрес Claude в Relay — `Claude@cloud-240267608411672576` (входящие Claude читает только во время работы треда;
будит его не Relay, а задача «кому: Claude»).

**Ответ ChatGPT в тот же тред Claude (26.10.2026).** Если тред Claude ждёт ответа ChatGPT (обсуждение, оценка), он ставит задачу и одно сообщение в Relay с просьбой ответить DM на адрес Claude и кратко в `result` задачи, а затем сам назначает себе отложенную проверку этого треда (`send_later`, ~20 мин; если ответа нет — ещё через 60 мин, не больше 3 проверок). При проверке читает `check_relay_inbox` и `result` задачи и пишет владельцу в том же треде. ChatGPT для такого ответа не ставит отдельную задачу «кому: Claude»: она запустила бы новую сессию Claude, а не этот тред.

**Пример — новая сцена (владелец 26.10).** Владелец пишет Claude «делаем сцену N» (чат проекта или задача «кому: Claude»).
Claude пишет промт и описание в мастер, ставит сцену в очередь, описывает нужные референсы (под замком, с проверками
`CLAUDE.md`, текст для рисования — `*.image-prompt.txt` рядом с будущим PNG) и ставит ChatGPT задачу «референсы S… + запуск по очереди».
Открытый чат ChatGPT Work рисует референсы, кладёт их в репозиторий и запускает сцену по `ops/TOPVIEW-FREE-LAUNCH.md` (безлимит, 0 кредитов).
Нужна правка промта под референс или проверка — ChatGPT ставит задачу «кому: Claude». Приёмка результата — владелец.

**Референсы рисует открытый чат ChatGPT Work (владелец 27.10.2026).** Запланированные задачи ChatGPT рисуют хуже, поэтому
задачу на рисование референсов они не берут и не закрывают. В тексте такой задачи первой строкой пишется «ВЫПОЛНЯЕТ ТОЛЬКО
ОТКРЫТЫЙ ЧАТ ChatGPT Work»; в Relay её не дублируют (Relay будит запланированный обработчик, а не открытый чат). Открытому
чату задачу передаёт сам владелец, Claude в ответе называет ему ID задачи. С 27.10 команда владельца **«Продолжай» в открытом Work** также передаёт ему такие открытые задачи `chatgpt/any` без отдельного сообщения с ID — `ops/CONTINUE-PROTOCOL.md`, раздел о продолжении в открытом ChatGPT Work. Запрет для часового и Relay-handler сохраняется.

## Границы

- Задача владельца — это его слово на то, что в ней написано, и только на это. Платные запуски Topview выполняет только сам владелец; агентам разрешён лишь безлимит с 0 кредитов.
  Одобрение, удаление, перезапуск и закрытие сцен без явной просьбы владельца не делаются.
- Творческий вопрос, который задача не решает однозначно, — `needs_owner` с вопросом, а не догадка.

## Чистка

Закрытые задачи старше 14 дней робот сначала сохраняет целиком в `archive/ops/owner-tasks-archive.json`, затем убирает из входящих в том же CAS-коммите. Архив создаётся при первом переносе; точные ID, текст, результат, SHA и неизвестные поля сохраняются. Повтор идентичной записи безопасен, конфликт одного ID останавливает перенос. Активные задачи и ожидающий подтверждения ответ Supabase остаются во входящих. Архив пишется атомарно раньше входящих; ошибка записи/push/readback не разрешает подтверждать успех. У задач с сайта история дополнительно остаётся в Supabase; у задач между агентами строки Supabase может не быть. Этот архив, как входящие, обслуживается без замка канона по CAS; проверяется при недельной чистке.
Задача в `taken` дольше 3 дней и `open` дольше 3 дней показываются в проверке здоровья канона (`canon-health.json`).

## Grok Bot и недоступный Claude · 01.11.2026

Grok зарегистрирован как дополнительный launcher; это не добавляет автоматически `to:grok` в UI, Supabase, валидаторы или Relay. Пока маршрут не реализован и не испытан, Grok принимает прямые поручения владельца в своём чате/проверенном личном Telegram; координация результата — канонические checkpoint и отчёт, запуск — общий протокол. Не направлять задачу «Claude» в расчёте, что она разбудит Grok. Для будущего общего inbox нужен отдельный совместимый переход с тестами и реальными адресами.

По сообщению владельца доступ к Claude потерян. Не стирать историю, не считать taken/unknown невыполненной и не забирать «только Claude» автоматически. Существующий порядок подхвата ChatGPT open>3ч сохраняется; конкретное переназначение владельца записывать явно с прежним адресатом. Статус задачи в GitHub остаётся источником результата, сообщения — только каналом доставки.

## Общая работа с Grok · 01.11.2026

Владелец разрешил адресат **grok** в задачах сайта. Маршрут: выбор Grok → Supabase owner_task/value=grok → штатный робот → этот же ops/owner-tasks.json → taken/result Grok → обратный результат на сайт. GitHub является хранилищем задач; ни выпадающий список, ни запись open не доказывают пробуждение Grok.

Grok Bot берёт только open to:grok либо явно свободную any, отдельным CAS сохраняет taken_by=grok:<исполнение>, taken_at; затем результат, доказательства/коммит и финальный статус. Grok Chat без подтверждённых коннекторов готовит материал и передаёт боту, не объявляет чужой коммит своим. Ничего не approve/delete/rerender по одному факту назначения. Чужие taken сохраняются; «только Claude» не забирать без правила ниже. Любой агент читает свежий main перед каждой записью, коллизия push = перечитать и пересчитать.

На каждом собственном существующем цикле Grok сначала читает новые to:grok; при no-op не пишет пустую квитанцию. Состояние задачи передаётся через GitHub, не через пересказ чата. Отчёт для обоих Grok: reports/grok-shared-ops-handoff.md. Приём реальным ботом — только по его собственной квитанции.

## Grok берёт задачи по тем же правилам, что ChatGPT · 01.11.2026 03:04

Решение владельца (Europe/Amsterdam, чат Grok Bot): «Делай сразу оба: быстрый способ и добавь Grok в список «Кому» на сайте». Это заменяет прежнюю оговорку, что правило open Claude >3ч не переносится на Grok.

- Grok Bot берёт: `to: grok`; `to: any`; `to: claude`, если задача остаётся `open` строго больше 3 часов по достоверному `created_at` (UTC; перед захватом перечитать свежий `main`). Непроверенная или будущая дата просрочку не доказывает. Задачи `source: self-heal` берёт так же, как `any`.
- Захват как у ChatGPT: маленький отдельный коммит в `main` (замок канона не нужен), `status: taken`, `taken_by: "grok:<кратко>"`, `taken_at`. Первый записавший `taken` владеет задачей: уже `taken` не трогать (чужую — пока она не старше 3 дней). Затем `done` / `needs_owner` / `cancelled` с `result`, `result_commit`, `closed_at`. Отклонённый push = перечитать файл и пересчитать с нуля.
- Опрос (уточнено 01.11.2026 03:16, владелец: «И В инструкциях поправь свое время»; 03:11: «Объединяй обе пары, пусть будет три рутины»): рутина «Поручения: Telegram и задачи с сайта» — каждые 10 минут с 08:00 до 23:50 Europe/Amsterdam (±5 мин; сервер сейчас срабатывает в :05, :15, …, :55) читает команды Telegram @Grok_vint_bot и `ops/owner-tasks.json`; прежний часовой опрос в :40 отменён. При отсутствии новых задач Grok в репозиторий ничего не пишет. Если новая `to: grok` пришла вне 08:00–23:50, она ждёт следующего опроса или прямого поручения владельца. Опрос сам не будит Grok и не доказывает запуск рутины: исполнение подтверждает собственная квитанция Grok.
- Границы прежние: платные генерации Topview только с отдельным явным «да» владельца на каждую; одобрение, удаление, перезапуск и закрытие сцен по факту назначения не делаются; неоднозначная или творческая задача — `needs_owner` с одним коротким вопросом. Референсы рисует только открытый чат ChatGPT Work (правило выше), такие задачи Grok не берёт. Результат Grok возвращается на сайт штатным роботом.
