## Что Grok Bot должен выполнить у себя

Начать с fresh main и задачи `to:grok` в `ops/owner-tasks.json`; взять её собственным `taken_by`/CAS, не подменять чужую квитанцию.

**Адаптер запуска.** Передавать настоящий `provider_run_id` из истории своего исполнения. Для Telegram — оригинальный Update из собственного авторизованного транспорта в `owner_command.telegram_update`: update_id; message.message_id/date/text; chat.id/type=private; from.id/is_bot=false. Chat ID и sender ID владельца сверяются с каноническим `owner_command_launch`. Пересылка/редакция/текст сайта не является командой. Для чата Grok требуются оригинальные conversation_id, message_id, sender_role=owner. Пароли, cookies, токены и полный сырой Telegram payload в публичный GitHub не писать: журнал сохраняет только нужные ID и данные намерения.

После полного фактического UI-preflight:

```sh
python3 scripts/launcher_coordination.py . prepare-intent \
  --actor /private/actor.json --scan /private/full-scan.json \
  --item-id EXACT_ITEM_ID --write
```

Команда изменяет локально **оба** файла: очередь и `ops/launcher-run-ledger.json`. Под собственной точной lease опубликовать их **одним CAS-коммитом** из fresh main, прочитать оба обратно; проверить `launcher_run_ledger.verify_binding(item, ledger)`, роль/lease и UI цену0. Только затем единственный Create в том же непрерывном исполнении. Программный интерфейс — `prepare_transaction`, возвращающий item и ledger. Один `prepare_intent` без публикации ledger недостаточен. Разрыв после intent = сверка, не второй клик. Ledger не чистить по TTL; не сбрасывать общий retry budget.

**Расписание.** Изменить существующую `topview-grok` на минуты :12/:27 всех24 часов, не создавать вторую рутину. Сохранить provider readback (ID, настройки, enabled), затем собственный настоящий run ID и результат. До подтверждения оставить `coverage.provider_state=pending_grok_apply_and_readback`. На каждом реальном цикле читать `ops/owner-tasks.json` и свежие сигналы launcher_health/очередь. `python3 scripts/grok_inbox.py .` — read-only помощник; сам ничего не запускает и не будит. Не заявлять webhook/10-минутное пробуждение, которого не подключали.

**Входы.** Открыть и скачать два Drive MP4 ниже в своём браузере; проверить SHA, размер,3с,72кадра,24fps,720p. Записать собственную проверку доступа в результат задачи. Успех скачивания у ChatGPT не равен фактическому доступу из Grok; ошибок входов не скрывать. Остальные обязательные будущие стыки готовятся только после настоящего результата источника.

**Адресат сайта.** Найти свою реальную задачу в inbox; собственным taken/result подтвердить приём. Ответ вернётся на сайт через штатного робота. Появление open-записи не равно доказанному пробуждению. При6/6 без изменений молчать; новый существенный блокер сохранить один раз, не спамить.

## Неизменные ограничения

Основной исполнитель при недоступном Work — ordinary ChatGPT :00 МСК; Work :55/Relay резерв; Grok помощник, GitHub-робот пишет телеметрию. Шесть физических видеослотов на все доски. Перед каждым Create полный свежий скан всех досок, точные master/SHA/входы/QC, свой замок/claim/intent, Unlimited0,720p,16:9,quantity1. Не менять приоритеты ради этой интеграции. Unknown не повторять. Success не approval. Не approve/delete/закрывать сцены автоматически.

**Первый реальный Create Grok всё ещё определяется живым first_real_create.owner_go_ahead. Это поручение по инфраструктуре не является отдельным разрешением его снять.** Никакого лишнего тестового ролика при6/6. После первого разрешённого запуска сохранить task ID и реальные параметры/0кредитов; только тогда подтверждать сквозную производственную работу.
