# AI Film Prompts — Full Sync Runbook

Эта инструкция нужна прежде всего ChatGPT/основному редактору проекта. Если старый чат потерян, сначала прочитать этот файл, затем `AI-PROJECT-GUIDE.md`, затем свежий `video-prompts.md` на Google Drive.

## Главное правило

**Google Drive → `AI Film Prompts Master/video-prompts.md` — единственный канонический редактируемый мастер промтов.**

## Обязательный статус ревизии и времени синхронизации

В верхней части канонического `video-prompts.md` всегда должен быть **заметный статусный блок**, а не незаметная строка. Он обязан показывать актуальные значения:

- количество **сцен к генерации/доработке**;
- количество **полных текстов промтов**;
- количество сцен в раннем блоке **«Сцены в работе»**;
- количество и номера сцен **⏳ в медленной генерации**;
- точное время **последней полной синхронизации** с датой, часами, минутами и UTC-смещением.

Текущий контрольный снимок проекта: **18 сцен к генерации/доработке · 21 полный текст промтов · 🛠️ 3 в раннем блоке (W5, W7, W8) · ⏳ 5 в медленной генерации (2, 6, 8, 14, 15)**.

Текущее зафиксированное время полной синхронизации: **2026-09-17 · 16:52 (+03:00)**.

При каждой **полной синхронизации** строка/пункт `Последняя полная синхронизация` и абзац `Синхронизация` в master-файле должны быть обновлены на фактическое время завершения синхронизации, в формате `YYYY-MM-DD · HH:MM (UTC offset)`, например `2026-09-17 · 16:38 (+03:00)`. Нельзя оставлять только дату без времени. Если меняются число сцен, prompt-текстов, work-items или slow-generation status, обновить этот статус одновременно во всех зеркалах и инструкциях.

## Обязательные правила отображения сайта и статусов

Эти правила считаются частью постоянной архитектуры проекта и должны сохраняться при любых будущих правках сайта, мастера, синхронизации или takeover:

1. **Монтажный разбор фильма для просмотра человеком** на публичном сайте должен открываться как отрендеренная HTML-страница GitHub Pages:  
   `https://virudik.github.io/ai-film-prompts/Seregius_montazhny_razbor.html`  
   Не использовать Google Drive preview этого `.html` как основную кликабельную ссылку на сайте: Drive может показывать исходный HTML-код. Drive-файл остаётся проектной копией/контекстом для ИИ, но не основным human-viewer URL.
2. Кнопка **`Инструкция для ИИ`** в боковой панели сайта должна всегда помещаться **в одну строку**. Не разрешать перенос слов/строк; для неё сохранять `white-space: nowrap` и при необходимости компактный размер шрифта/отступов.
3. Для сцен в медленной генерации использовать **одинаковую видимую надпись везде**: `⏳ В МЕДЛЕННОЙ ГЕНЕРАЦИИ`.
   - В строке сцены в оглавлении сначала показывается название сцены, **на следующей строке** — `⏳ В МЕДЛЕННОЙ ГЕНЕРАЦИИ`.
   - Не ставить `⏳` перед названием сцены.
   - Не ставить тире перед статусом.
   - Саму фразу `⏳ В МЕДЛЕННОЙ ГЕНЕРАЦИИ` не переносить внутри себя; в веб-viewer она должна помещаться целиком (`white-space: nowrap`).
   - В отдельной таблице slow-generation использовать ту же точную формулировку.
   - В полном разделе сцены статус также должен визуально стоять отдельной строкой той же формулировкой; пояснение `уже запущено / не запускать повторно` давать отдельным текстом, а не частью другой версии статуса.
4. Статус медленной генерации по-прежнему является инвариантом: при добавлении/снятии его нужно синхронно обновлять в верхнем статусном блоке, отдельном slow-generation блоке, строке оглавления и полном разделе сцены.

Нельзя считать локальную копию, GitHub, GitHub Pages, Notion или ChatGPT Library более свежими без сверки с Drive. Если пользователь сообщает, что Work или он сам редактировал Drive, сначала заново прочитать Drive-мастер и сохранить эти изменения.

## Как устроен и как был создан проект

Архитектура специально сделана так, чтобы проект восстанавливался без старого чата и без памяти модели:

1. **Google Drive** хранит канонический редактируемый `video-prompts.md` и проектный контекст.
2. **GitHub repository `virudik/ai-film-prompts`** хранит публичное read-only зеркало Markdown-файлов.
3. **`index.html` в корне GitHub** — веб-просмотрщик. Он не содержит отдельный мастер, а при открытии загружает root `video-prompts.md`.
4. **GitHub Pages** публикует `main` / root по адресу `https://virudik.github.io/ai-film-prompts/`.
5. **`.github/workflows/sync-from-drive.yml`** — автоматическая страховочная синхронизация Drive → GitHub. Она запускается по расписанию и через `SYNC-TRIGGER.txt`.
6. **ChatGPT Library** хранит внутренние зеркала, но не является источником истины.
7. **Notion `AI Video Prompts — Master Hub`** хранит навигацию, текущий статус и копии инструкций, но не отдельный мастер промтов.

Если систему приходится восстанавливать с нуля: сначала восстановить Drive-папку и канонический `video-prompts.md`, затем GitHub root `video-prompts.md`, `index.html`, инструкции и workflow, после чего включить GitHub Pages для `main` → `/ (root)`. Последним шагом восстановить Notion Hub и Library-зеркала.

## Как обслуживать мастер-файл

При добавлении новой сцены обязательно одновременно:

1. выбрать следующий свободный номер;
2. добавить строку в верхнюю таблицу оглавления;
3. добавить полноценный раздел `<a id="scene-N"></a>` + `## Сцена N — ...`;
4. обновить число сцен/полных промтов в строке ревизии;
5. убрать соответствующую запись из `Сцены в работе`, если она стала полноценной сценой;
6. проверить отсутствие старой версии той же сцены в другом месте;
7. если есть осознанные варианты A/B, держать их внутри **одной сцены**, а не создавать два мастер-файла.

Когда ролик окончательно принят и промт больше не нужен — удалить сцену из активного мастера и из оглавления. Мастер — очередь активной генерации/доработки, а не архив всех прошлых промтов.

## Как обслуживать сайт

Сайт не редактируется отдельно от мастера.

- Источник сайта: GitHub root `video-prompts.md`.
- `index.html` должен динамически читать этот файл с `cache: no-store`.
- После любого изменения мастера нужно добиться, чтобы root GitHub получил **ту же утверждённую версию**, затем дождаться Pages deployment.
- После деплоя проверить минимум: актуальную ревизию, последнюю сцену в верхней таблице, последнюю сцену в боковой навигации и одну характерную фразу из нового/исправленного промта.
- Если сайт отстаёт, сначала проверять GitHub root; если root старый — проблема синхронизации, а не кэша браузера.
- Не считать Drive `video-prompts.html` источником для GitHub Pages. Это отдельный удобный viewer/резервное представление.

## Что означает просьба пользователя «обнови мастер везде / синхронизируй всё»

Порядок обязателен:
1. заново прочитать свежий Drive `video-prompts.md`;
2. внести только согласованные изменения в тот же Drive-файл;
3. проверить верхнюю таблицу и полные `## Сцена N` секции;
4. проверить slow-generation block + `⏳` в строках оглавления + status в разделах сцен;
5. обновить Drive `video-prompts.html`;
6. обновить GitHub root master и изменённые instruction-файлы;
7. дождаться/проверить GitHub Pages deployment;
8. обновить Library mirrors;
9. обновить Notion Hub и Notion-копии инструкций, если правила/статус менялись;
10. проверить публичную страницу, а не ограничиваться локальным файлом.

## Частые ошибки — НЕ ПОВТОРЯТЬ

- Сцена есть в `## Сцена N`, но отсутствует в верхней таблице.
- В slow-generation block сцена есть, а в TOC нет пометки `⏳`.
- Локальный файл обновлён, Drive/GitHub — нет.
- GitHub root свежий, а Pages deploy ещё не закончен.
- Считать Notion отдельным prompt master и редактировать там промты независимо.
- Использовать старые split `_source/part-*` как источник истины.
- Говорить «синхронизировано», не проверив внешние копии.
- Ссылка на монтажный разбор ведёт на Drive preview и показывает исходный HTML-код вместо страницы.
- Кнопка `Инструкция для ИИ` переносится на две строки.
- Slow-generation статус написан несколькими разными способами или стоит в той же строке с названием сцены.

## Sanity check после каждой правки мастера

Перед завершением любой правки `video-prompts.md` обязательно проверить оба уровня структуры:

1. **Верхняя таблица / оглавление master-файла.**
   - каждая активная сцена имеет строку;
   - номер и заголовок совпадают с полноценным разделом ниже;
   - slow-generation сцены имеют `⏳ В МЕДЛЕННОЙ ГЕНЕРАЦИИ` на отдельной следующей строке.

2. **Полные разделы `## Сцена N`.**
   - новая сцена присутствует как полноценный раздел;
   - удалённая сцена удалена и из таблицы, и из тела;
   - номер/название/референсы не расходятся с верхней строкой.

3. **Slow-generation status.**
   - одна и та же сцена отражена в global slow-generation block, dedicated table, TOC row и full scene section;
   - при снятии статуса убрать его везде одновременно.

4. **После синхронизации GitHub/Pages** отдельно убедиться, что внешний viewer показывает последние сцены и статусы; не считать локальный или Drive-файл доказательством, что сайт уже обновился.
