## Как устроен и как был создан проект

Архитектура специально сделана так, чтобы проект восстанавливался без старого чата и без памяти модели:

1. **Google Drive** хранит канонический редактируемый `video-prompts.md` и проектный контекст.
2. **GitHub repository `virudik/ai-film-prompts`** хранит публичное read-only зеркало Markdown-файлов.
3. **`index.html` в корне GitHub** — веб-просмотрщик. Он не содержит отдельный мастер, а при открытии загружает root `video-prompts.md`.
4. **GitHub Pages** публикует `main` / root по адресу `https://virudik.github.io/ai-film-prompts/`.
5. **`.github/workflows/sync-from-drive.yml`** — автоматическая страховочная синхронизация Drive → GitHub. Она запускается по расписанию и через `SYNC-TRIGGER.txt`.
6. **ChatGPT Library** хранит внутренние зеркала, но не является источником истины.
7. **Notion `AI Video Prompts — Master Hub`** хранит навигацию, текущий статус и копии инструкций, но не отдельный мастер промтов.

Если систему приходится восстанавливать с нуля: сначала восстановить Drive-папку и канонический `video-prompts.md`, затем GitHub root `video-prompts.md`, `index.html`, инструкции и workflow, после чего включить GitHub Pages для `main` → `/ (root)`. Последним шагом восстановить Notion Hub и Library-зеркала.

## Как обслуживать мастер-файл

При добавлении новой сцены обязательно одновременно:

1. выбрать следующий свободный номер;
2. добавить строку в верхнюю таблицу оглавления;
3. добавить полноценный раздел `<a id="scene-N"></a>` + `## Сцена N — ...`;
4. обновить число сцен/полных промтов в строке ревизии;
5. убрать соответствующую запись из `Сцены в работе`, если она стала полноценной сценой;
6. проверить отсутствие старой версии той же сцены в другом месте;
7. если есть осознанные варианты A/B, держать их внутри **одной сцены**, а не создавать два мастер-файла.

Когда ролик окончательно принят и промт больше не нужен — удалить сцену из активного мастера и из оглавления. Мастер — очередь активной генерации/доработки, а не архив всех прошлых промтов.

## Как обслуживать сайт

Сайт не редактируется отдельно от мастера.

- Источник сайта: GitHub root `video-prompts.md`.
- `index.html` должен динамически читать этот файл с `cache: no-store`.
- После любого изменения мастера нужно добиться, чтобы root GitHub получил **ту же утверждённую версию**, затем дождаться Pages deployment.
- После деплоя проверить минимум: актуальную ревизию, последнюю сцену в верхней таблице, последнюю сцену в боковой навигации и одну характерную фразу из нового/исправленного промта.
- Если сайт отстаёт, сначала проверять GitHub root; если root старый — проблема синхронизации, а не кэша браузера.
- Не считать Drive `video-prompts.html` источником для GitHub Pages. Это отдельный удобный viewer/резервное представление.

2. `SYNC-RUNBOOK.md`;
3. `AI-PROJECT-GUIDE.md`;
4. свежий Drive `video-prompts.md`.

Если в Claude подключён тот же Google Drive аккаунт пользователя, он может редактировать канонический `video-prompts.md` в том же file ID. Содержательные изменения сайта (сцены/промты) затем подхватываются схемой Drive → GitHub root master → Pages. Для правок самого `index.html` Claude нужен GitHub write connector/authorization в его собственной среде. Наличие публичной инструкции само по себе не выдаёт write-доступ. Не использовать API keys/PAT, присланные в чат.

После возвращения ChatGPT Claude должен оставить handoff: какие файлы/сцены менял, синхронизирован ли GitHub, проверен ли Pages, обновлён ли Notion.

## Что означает просьба пользователя «обнови мастер», «внеси везде», «полная синхронизация»

Это **не** означает только отредактировать `/mnt/data/video-prompts.md`.

После утверждённой правки нужно довести изменение по всей цепочке:

1. **Fresh read:** заново прочитать канонический Drive `video-prompts.md` и проверить, не появились ли там более свежие изменения от пользователя/Work.
2. **Edit:** внести только нужные правки в мастер, не уничтожая несвязанные сцены.
3. **Integrity check:** проверить:
   - число сцен и полных текстов промтов в строке ревизии;
   - строки оглавления для всех активных сцен;
   - ссылки `#scene-N`;
   - блок `Сцены в работе`;
   - статусы медленной генерации;
   - отсутствие дубликатов сцены;
   - отсутствие старого направления/диалога/референсной ошибки в другом месте файла.
4. **Slow-generation status:** если сцена отмечена как медленная, статус должен быть одновременно:
   - в верхнем блоке `⏳ Сейчас в медленной генерации`;
   - в таблице оглавления рядом с номером сцены;
   - в самой секции сцены строкой `Статус генерации`.
   Если пользователь снимает статус — удалить его из всех трёх мест.
5. **Local mirrors:** обновить текущие локальные рабочие копии `video-prompts.md` и, если существует, `video-prompts.html`. HTML — производный, не источник истины.
6. **Drive:** заменить содержимое канонического Drive `video-prompts.md` **в том же file ID**. Если изменены инструкции — обновить те же Drive-файлы инструкций. Обновить Drive HTML-viewer при полной синхронизации.
7. **ChatGPT Library:** заменить существующие Library-зеркала, а не создавать `copy`, `v2`, `final`.
8. **GitHub:** обновить root `video-prompts.md` и изменённые инструкции. Public viewer `index.html` динамически читает root `video-prompts.md` с `cache: no-store`.
9. **GitHub Pages:** убедиться, что commit на `main` вызвал Pages deployment и он завершился `success`. Не говорить, что сайт обновлён, пока это не проверено.
10. **Notion Hub:** обновить только навигацию/текущий производственный статус/правила синхронизации. Не копировать туда полный мастер как независимую версию.
11. **Verify end-to-end:** после деплоя открыть/fetch публичный raw master или сайт и убедиться, что новая фраза/статус реально присутствует.
12. Только после проверки сообщать пользователю, что полная синхронизация завершена.

## GitHub архитектура

`index.html` — read-only viewer. Он загружает `video-prompts.md` из корня репозитория при открытии страницы.

Поэтому для изменения содержания сайта не надо вручную переписывать HTML сцены: нужно обновить root `video-prompts.md` и дождаться Pages deployment.

Старый `_source/part-*.md` + `build-master.yml` — исторический обход ограничения размера. **Не использовать его как источник истины.** Он может быть опасен, если workflow вручную запустить со старыми частями. Предпочтительная схема: Drive → root GitHub `video-prompts.md` → Pages viewer. Если старый build workflow всё ещё существует, его нельзя вручную запускать без предварительной синхронизации `_source`; лучше держать его отключённым/удалённым.

## Автоматическая Drive → GitHub синхронизация

Workflow `.github/workflows/sync-from-drive.yml` используется как страховка/зеркало. Он должен скачивать только проверенные канонические файлы с Drive и никогда не коммитить страницу Google Sign-In вместо Markdown.

После ручной правки из ChatGPT допустимо либо:
- обновить GitHub напрямую тем же содержимым, затем проверить Pages;
- либо обновить Drive и запустить sync workflow через `SYNC-TRIGGER.txt`, затем дождаться его успешного завершения.

При полной синхронизации предпочтительно иметь одинаковое содержимое Drive и GitHub, а не ждать очередного cron.

## Notion

Notion `AI Video Prompts — Master Hub` — это хаб, а не мастер. Там должны быть:
- стабильные ссылки на Drive/GitHub/site;
- текущие сцены в медленной генерации;
- краткая отметка о последнем крупном обновлении;
- ссылка на этот runbook;
- напоминание, что Drive — канон.

## Если сайт показывает старое

Проверять в таком порядке:
1. свежий ли Drive master;
2. свежий ли GitHub root `video-prompts.md`;
3. совпадают ли **оба оглавления**: верхняя таблица в Markdown и список `## Сцена N` в теле файла;
4. завершился ли Pages deployment;
5. открыть публичный viewer и убедиться, что боковая навигация построилась до последней сцены, а не обрывается раньше;
6. если всё свежее — перезагрузить страницу/очистить вкладку. Viewer использует `cache: no-store`, но браузер или Pages CDN может дать краткую задержку.

**Контроль на текущей ревизии 2026-09-17:** после синхронизации сайт должен видеть сцены 16, 17 и 18 как отдельные разделы. Если боковая навигация заканчивается на 15, значит GitHub root или Pages всё ещё отстаёт — нельзя сообщать пользователю, что синхронизация завершена.
