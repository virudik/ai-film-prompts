## 4. Confirmed semantic drift

The following differences are production-relevant, not whitespace-only.

### 4.1 `AI-PROJECT-GUIDE.md` — high-value drift

The Drive version contains safety/detail that the GitHub version omits or expresses less completely, including:

- scheduled `sync-from-drive.yml` safety-net approximately every 30 minutes;
- mandatory fresh-read of Drive master before every actual write;
- removal of a scene from active master after successful generation/closure when the prompt is no longer needed;
- explicit exact slow label plus prohibition on relaunching a slow scene before result/error/user approval;
- ISO dates limited to machine/API/JSON fields while human dates remain `DD.MM.YYYY`;
- stronger reference rule that a textual ref name is not a substitute for the actual image/video;
- expanded model-role wording;
- explicit Gemini guard: do not build a site/app merely because a project URL was provided;
- clearer conflict priority phrasing tied specifically to fresh Drive state.

**Risk if GitHub copy is used by an external AI:** incomplete safety behavior, especially around fresh reads, slow renders, references, and role boundaries.

### 4.2 `SYNC-RUNBOOK.md` — low-volume but real drift

This file is the closest pair: only 117 bytes difference in total size, but byte hashes still differ.

Confirmed meaningful Drive additions include permanent project pointers for:

- `film-analysis.md`
- `film-backlog.md`

The Drive version is therefore the more complete recovery/operations reference.

**Risk:** low-to-medium by itself, but important because this file is intended to be normative.

### 4.3 `USER-GUIDE.md` — substantial drift

The Drive version has a much fuller invariant block than GitHub and explicitly includes safeguards that are abbreviated or absent in the mirror, including:

- generated/read-only nature of `project-status.json`;
- scheduled sync safety-net;
- fresh Drive read before writes;
- scene closure/removal rule;
- exact slow label and no-relaunch rule;
- detailed date convention;
- current site invariants;
- legacy builder prohibition;
- stronger `ГОТОВО` verification rule.

**Risk:** a human or AI using only GitHub sees a simplified owner procedure that is materially less defensive than the Drive version.

### 4.4 `README-AI-SYNC.md` — substantial drift

The Drive version contains the expanded v2 immutable rules while GitHub still has a shorter technical summary.

Missing/less explicit in GitHub include the same critical protections around:

- scheduled safety-net sync;
- fresh-read before write;
- closure/removal of finished scenes;
- exact/no-rerun slow behavior;
- richer date/site invariants;
- mandatory verification before declaring completion.

**Risk:** external automation/editor can infer that the short GitHub README is the full protocol when it is not.

### 4.5 `CLAUDE-TAKEOVER-RUNBOOK.md` — substantial drift

The Drive takeover document contains the expanded invariant set and stronger safeguards; the GitHub copy is significantly shorter.

Production-relevant Drive additions include:

- scheduled sync safety-net;
- mandatory fresh-read before write;
- scene closure/removal rule;
- exact slow label + no duplicate slow launch;
- stronger date/site invariants;
- stronger actual-reference requirement.

Separate V3.5 issue still remains: takeover must verify that the active Drive connector can replace raw contents **in the same file ID** before accepting editor responsibility.

**Risk:** high specifically in recovery/takeover scenarios, because the document exists for failure conditions.

## 5. Root cause

Current `.github/workflows/sync-from-drive.yml` deterministically downloads and repairs:

- canonical Drive `video-prompts.md`;
- generated `project-status.json`.

It does **not** download/compare/repair the five canonical instruction files.

Therefore:

- `video-prompts.md` stays byte-identical between Drive and GitHub;
- instructions drift whenever Drive copies are updated without an explicit GitHub instruction checkpoint.

This is consistent with the observed hashes and does not require a second master or a source-of-truth migration.

## 6. Phase 0 decision

### Keep unchanged

- Drive `video-prompts.md` remains the only editable prompt master.
- GitHub remains read-only mirror + Pages source.
- Current slow protection remains unchanged.
- Stable sparse scene IDs remain unchanged.
- Library/Notion remain backup/documentation layers.

### Fix in Phase 1

Extend the existing deterministic sync/validation path so that the five small instruction files:

1. are downloaded from their existing Drive file IDs;
2. are validated as real Markdown, not login/HTML responses;
3. are compared byte-for-byte with GitHub copies;
4. are automatically repaired in the GitHub mirror when Drive differs;
5. contribute hashes/status to generated `project-status.json` schema v3.

No manual duplicated “instruction freshness” field should be maintained.
